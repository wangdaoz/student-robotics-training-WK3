          Step 1 Check what the terminal actually printed

                     Scroll up in your terminal (or re-run the command) and look for a Python traceback ending in an error like RuntimeError, ValueError, or FileNotFoundError, versus a clean JSON summary block. If you see a traceback, paste the last ~10 lines here -- that pinpoints the exact fix needed.

          Step 2 Confirm you're at repo root when running it
                     
                      Run <pwd (or cd)> and <ls models/berkeley/> from where you launched the command. If models/berkeley/ isn't visible from your current directory, the script's relative MODEL_PATH won't resolve and it will fail with a mesh/model loading error before it ever reaches the logging code.

          Step 3 Search the whole repo for the file, in case it landed elsewhere
                 Run <find . -name 'control_berkeley_joint.csv'> from the repo root. If the script actually succeeded but was run from a different working directory than you expect, the evidence/logs/ folder may have been created relative to that other location instead.

          Step 4 Re-run with an explicit, absolute log path to isolate the problem

                Try <python scripts/control_berkeley_joint.py --ctrl 1.5 --duration 3.0 --log-file /tmp/test_control_log.csv>. If /tmp/test_control_log.csv appears, the logging code itself is fine and the issue is specific to the evidence/logs/ path (e.g. a permissions issue, or the directory being on a read-only mount). If it still doesn't appear, the script is failing before the logging step regardless of path.

          Step 5 Check the exit code
          
               Right after running the command, run echo $?. 0 means the script completed normally; any nonzero value confirms it crashed, even if the error scrolled past or was suppressed.

        Then, I gave all results of these steps to Claude, "For Step 1, terminal printed nothing, Step 2 is okay*repo root), Step 3, after inputted <find . -name 'control_berkeley_joint.csv'>, nothing displayed. In Step 4,  /tmp/test_control_log.csv appears not appear. Step 5, exit code is 0."

        Finally, after analysis, it concluded: That combination — zero output, zero error, exit code 0, and no file anywhere — actually points to one specific, very common cause: the script never actually calls main().

         If the if __name__ == "__main__": main() guard at the very bottom of the file is missing, mis-indented, or got dropped during the JSON→CSV edit, Python will happily parse and "run" the file — defining all the functions — and then just... stop. No code inside main() ever executes, so there's no print, no file write, and no error. The process exits cleanly with code 0 because nothing went wrong; nothing ran at all.

         I check <if __name__ == "__main__": main()> immediately and discovered that I indeed missed it. 
         Finally, I added this segment and successfully re-ran the script to get the expected results and log file.
