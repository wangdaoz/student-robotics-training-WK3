### How I investigated

          I thought this task for a short time. Then, I asked Claude Code: "I'm a little confused on Engineering Task 11: Write scripts/control_simple_arm.py to command a joint through a safe range. Can you teach me do this task"

          It guided me how to think it. 
          The core idea: command the actuator, not the joint:
                                       The biggest trap in this task is sitting right in the ticket's Common Mistakes list: "Moving qpos directly and calling that actuator control." Here's the difference:

                                        Ran a command

                                        Setting data.qpos directly teleports the joint — it bypasses physics entirely. It's not "control," it's cheating the display. Notice how one physics step already starts dragging it back toward equilibrium, because nothing is actually holding it there.

                                        The correct way is to write to data.ctrl, which feeds into the actuator you defined in the XML:

                                        Ran a command

                                        That's a real actuator at work — data.ctrl[0] = 1.0 sets a target, and the position actuator (kp="20" in your XML) pulls the joint toward it over many physics steps, not instantly. Notice it actually overshoots past 1.0 before settling back down — that's the joint's momentum and damping interacting, exactly the kind of oscillation the ticket's "why might a joint oscillate" prompt is pointing at.

### What I Learned
     Command actuator to control target joint.

     For python codes:
             '''
                 qpos_addr = model.jnt_qposadr[model.joint(joint_name).id]
                 isolation_qpos_addr = model.jnt_qposadr[model.joint(ISOLATION_JOINT).id]
             '''
              ● model.joint(...)
                
                 looks joint up by name in the model; Returning a small "view" object with info about it.
                 This is the name-based lookup habit from before, applied to joints instead of actuators.

              ● model.jnt_qposadr(...)
                
                 Each joint corresponds an entry, so for each MjModel object, there exists an table: data.pos array.
                 This method looks up the table and search where the target joint's position value(index) actually lives.
